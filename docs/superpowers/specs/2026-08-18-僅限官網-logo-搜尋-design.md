# 僅限官網的官方 Logo 搜尋

日期：2026-08-18  
狀態：已由產品負責人批准

## 目標

提高官方 Logo 的命中率，同時把品牌誤認與不必要的第三方依賴降到最低。
系統只從已驗證的公司官網取得 Logo；官網沒有安全、可預覽的候選時，直接請
使用者手動上傳，不呼叫任何第三方 Logo API。

## 使用者結果

使用者在已採用題目的「輪播製作」區塊會看到：

1. 系統利用公司名、標題、切角、正文與查證來源辨認正確官網。
2. 系統依序檢查官網首頁、品牌素材頁與瀏覽器渲染後的動態內容。
3. 找到時顯示最多三張候選，以及官方網域、Logo 類型與判定理由。
4. 每張候選都必須由使用者按下「確認這是官方 Logo」才會儲存。
5. 找不到時清楚說明官網沒有可用候選，保留重新搜尋與手動上傳。
6. 缺少 Logo 只阻止輸出七張圖，不阻止產生文字草稿。

## 系統結構

```text
Idea 內容與查證來源
        ↓
official_site：辨認並驗證官方網站
        ↓
logo_discovery：擷取靜態官網素材
        ↓ 無候選
logo_browser：渲染動態官網後再擷取
        ↓
logo_search：整理候選或回傳可復原錯誤
        ↓
Streamlit 工作台：顯示證據、等待人工確認
        ↓ 使用者確認
assets.store_logo：唯一正式寫入入口
```

各單元責任：

- `official_site`：只處理公司身分與官方網域，不下載或決定 Logo。
- `logo_discovery`：只處理官方網站內的 SVG、透明 PNG 與內嵌 SVG。
- `logo_browser`：只有靜態 HTML 無候選時才啟動 Chromium，取得動態頁面內容。
- `logo_search`：編排前三者，不接觸資料庫，也不採用候選。
- 工作台：暫存候選、顯示證據並接收人工確認。
- `assets.store_logo`：驗證檔案與來源後，才寫入品牌資產。

## 資料流與信任邊界

### 官方網站辨認

輸入不是只有公司名。系統同時使用：

- 公司名稱
- 題目標題
- 採用角度
- 正文
- 已保存的查證來源

可信公司目錄若明確連到外部官網，可作為強證據；否則使用 Tavily 搜尋可能的
官方網站，再下載候選頁面比對公司名與產品脈絡。編輯媒體、社群網站、App 商店、
百科與素材下載站不可被當成官網。同名網站證據相同時，不自動猜測。

Tavily 的角色只限於尋找公開官網網址，不提供或代理 Logo 檔案。

### 官網素材擷取

靜態路徑包含：

- `<img>` 的 `src` 與 `srcset`
- 安全的內嵌 SVG
- JSON-LD `Organization.logo`
- 明確標示為品牌或 Logo 的 CSS 背景圖
- 同網域的品牌、媒體、新聞與素材頁

靜態路徑沒有結果時才啟動瀏覽器渲染，檢查 JavaScript 產生的相同類型素材。
所有候選仍須通過既有 SVG／透明 PNG 安全驗證。

### 人工確認

「候選」不等於「官方資產」。工作台最多顯示三張候選，每張包含：

- 已解析的官方網域
- 來源標籤「官網」
- 類型：完整 Logo、品牌符號或網站圖示
- 判定理由
- 官方頁面與原始檔連結

搜尋、預覽與拒絕都不寫入資料庫。只有使用者確認的那一張會經過
`assets.store_logo` 儲存。拒絕一張只從目前候選清單移除，不重新呼叫外部服務。

## 錯誤與復原

錯誤分為三層：

- `official_site`：無法確認正確官網；提供重新搜尋與手動上傳。
- `official_assets`：官網靜態與動態路徑都沒有安全候選；提供重新搜尋與手動上傳。
- `service`：官網或搜尋服務暫時無法讀取；提供重新搜尋與手動上傳。

錯誤畫面不得顯示原始供應商回應、憑證或內部例外。所有錯誤都不影響正文與
文字輪播草稿，只有缺少已確認 Logo 時維持「不可輸出七張圖」。

## 安全、隱私與成本

- 不使用任何第三方 Logo API，也不新增相關憑證、設定或網路請求。
- 只向公開網頁與既有 Tavily 搜尋送出公開公司資訊與內容脈絡。
- 不自動把候選寫入資料庫或正式素材目錄。
- Logo 原始檔連結移除 query string 後才顯示，避免網址參數外洩。
- 瀏覽器只在靜態擷取失敗時啟動，以控制 CPU、記憶體與等待時間。
- 沿用免費服務與既有依賴，不新增付費成本。

## UI 方向

沿用現有深淺色品牌系統，不重新設計整個工作台。候選證據卡維持垂直閱讀順序，
先顯示身分證據，再顯示圖片與操作。桌機與 375px 手機都必須無水平捲動；按鈕需
具備 hover、focus 與按壓回饋，並遵守減少動態偏好。

設定頁不顯示任何第三方 Logo 服務欄位，因為產品不再需要這類憑證。

## 測試與驗收

### 單元與整合測試

- 官網有安全候選時，回傳最多三張且不寫入資料庫。
- 官網靜態無候選時，才呼叫動態瀏覽器路徑。
- 官網所有路徑皆無候選時，回傳 `official_assets` 復原錯誤。
- 工作台收到完整 Idea 脈絡與來源包。
- 三張候選皆有官方網域、類型、理由與獨立確認按鈕。
- 確認第二張只保存第二張；拒絕第一張保留其他候選且不重新搜尋。
- 設定頁沒有第三方 Logo 服務欄位或環境變數狀態。
- 全專案文字掃描不得出現已移除的供應商名稱或環境變數名稱。

### 真實邊界

- SUN 必須解析為 `sunapp.ai`，不得選到同名組織或其他產品。
- Moove 官網必須能取得一張通過本機安全驗證的 Logo。
- 真實測試不得寫入正式資料庫，也不得自動確認候選。

### 視覺與正式流程

- 以資料庫副本完成兩輪 1280×800 與 375×812 截圖自檢。
- 驗證候選、空狀態、錯誤、手動上傳與已確認狀態。
- 合併後在 `main` 重跑全套測試，推送並重啟既有 localhost 正式服務。
- 正式驗收只預覽候選，不替使用者做 Logo 身分決策。

## 不做的事

- 不從搜尋結果圖片、社群網站、媒體文章或素材下載站直接採用 Logo。
- 不使用第三方 Logo API 作為備援。
- 不依公司名稱猜測圖片，也不自動確認任何候選。
- 不改變既有 Logo 上傳格式、安全限制、資料表或正式輸出尺寸。

## 完成定義

正式程式、設定、環境範本、測試與現行文件都只描述「官網搜尋 → 人工確認／手動
上傳」流程；供應商專用模組與測試已刪除；聚焦測試、真實官網契約、全套測試與
兩輪視覺 QA 均通過，正式 localhost 核心流程可用且沒有新增錯誤。
