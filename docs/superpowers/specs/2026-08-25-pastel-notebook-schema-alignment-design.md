# 粉彩手帳模板內容契約對齊設計

## 目標

保留已核可的粉彩手帳視覺、紙張層次與四種手繪呆一布動作，將七頁所有內容槽改為現有 `CarouselDraft` 的正式欄位，使原型可以不修改 AI 生成器資料格式就進入後續正式 Renderer 實作。

## 資料對照

1. `cover`：標題、一句話定位、產業分類。
2. `who`：標題、白話定位、基本資料。
3. `problem`：標題、誰受影響、原本的代價、三個 `problem-chain` 節點。
4. `how-ai`：標題、傳統做法、AI 的角色、人仍負責、本頁要記住、三個 AI 流程節點。
5. `results`：標題、代表使用者、使用前後、購買關係、三個 `before-after` 節點。
6. `why-care`：標題、三個觀察訊號、證據限制、三個 `signals` 節點；不預設一定有百分比。
7. `cta`：畫面改為系列社群帳號的固定行動邀請；保留給讀者的問題與互動邀請。現有標題與收束結論欄位在原型中隱藏，僅作舊草稿相容。

每個可替換內容槽以 `data-content-key` 標記正式編輯鍵。所有鍵保持公司中立，不出現 SUN 或其他測試公司的固有內容。

## 視覺策略

- 保留藍色方格底、彩色襯紙、雙膠帶與深墨線，但所有主要紙框、資訊框與流程框保持水平垂直；手帳感只由材質、膠帶、色塊與手繪角色表現，不靠旋轉框線。
- 每頁最後一個主要內容模組至少延伸到畫布高度 74%；角色與純裝飾不計入，避免用插圖假裝填滿資訊空間。
- 前六頁共 26 個語意內容面統一使用第 3 頁的直角便利貼語言：粉彩紙面、無完整描邊、可見的紙片陰影。第 7 頁純文字 CTA、Logo 區與外層白紙不是內容面，不套用便利貼。
- 每張便利貼加入三個實體材質提示：上緣 15% 的黏膠層色差、極淡紙纖維顆粒、右下角小幅掀角。材質層不得改變內容幾何或重新旋轉紙張。
- 第 3–6 頁都同時呈現敘事段落與三節點圖解，不把兩種資料硬塞進同一欄。
- 第 5 頁改為清楚的使用前／轉變／使用後對照，不再呈現商業模式。
- 第 6 頁使用三張訊號便條與證據限制，不使用 `XX%` 這種資料假設。
- 四種角色動作依頁面語意重用：招手、搜尋、思考、完成。
- 第 3 頁三個問題節點使用等寬直立便利貼；第 4 頁三個 AI 流程節點使用等寬橫列，下方四段補充維持 2×2，避免內容區形成零碎大洞。
- 第 3 頁改為左右敘事：左欄交代受影響者與原本代價，右欄依序呈現問題出現、摩擦累積、形成代價。三個因果節點必須由上往下等寬排列，角色只能留在標題區。
- 第 2–6 頁必須形成 `公司身分 → 問題 → AI 機制 → 使用結果 → 證據` 的跨頁故事。後一頁要回答前一頁留下的問題，不得各自生成互不相干的資訊卡。
- 高密度不得靠縮小字體：第 2–6 頁正文計算字級不得低於畫布寬度 1.55%；若內容過長，先刪重複句，再調整卡片內距，不得截斷或縮到門檻以下。
- 第 7 頁是純社群 CTA，不再做第二次內容總結。紙張正中央只放 2–3 句，現行固定為「喜歡這類內容嗎？」、「追蹤 @社群帳號」、「下一間想看哪家公司？留言告訴我們。」；不得加入帳號卡、提問卡、提示膠囊或底部行動列。

## 邊界

本輪只修改被 `.gitignore` 排除的視覺伴隨原型與其契約，不修改正式 Renderer、SQLite、提示詞、舊草稿或正式站。正式接線另開一輪以 Python 與瀏覽器測試保護。

## 驗收

- 七頁正式欄位鍵完整且沒有錯誤的商業模式／百分比假設。
- 主要框計算後的 `transform` 全為 `none`，內容模組的垂直使用率至少 74%。
- 前六頁 26 個語意內容面都必須無邊框、有紙片陰影且保持直角。
- 前六頁 26 個便利貼都必須具有黏膠層、紙紋與折角；折角不得造成內容越界。
- 1280×800 與 375×812 無水平溢出、文字裁切或關鍵遮擋。
- 七張頁面仍屬同一粉彩手帳視覺系統。
- 瀏覽器 console 0 errors／0 warnings。
- 第 3／4 頁主要節點等寬，最後內容模組與紙張底邊空隙不超過紙張高度 12%。
- 第 7 頁不得顯示 `TAKEAWAY`、「最後，帶走這個觀察」、「收束結論」或任何 CTA 內容卡；2–3 句文字的視覺中心與紙張中心偏差不超過紙張高度 8%。
- 第 2–6 頁可見正式內容欄位至少分別達到 110、175、190、175、190 個中文字，且所有文字留在所屬語意內容面內。
- 七頁故事角色順序固定為 `hook／identity／problem／mechanism／outcome／proof／cta`。
