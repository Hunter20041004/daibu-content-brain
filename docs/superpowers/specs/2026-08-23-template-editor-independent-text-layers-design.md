# 系列模板編輯器：七頁獨立文字層設計

日期：2026-08-23  
狀態：已由使用者確認方向 A，等待書面規格複核

## 1. 背景與問題

系列模板編輯器目前把部分文字與色塊包在同一個 `data-layout-id` 元素內。例如第二頁的「基本資料」元素同時包含：

- 深藍背景；
- 橘色欄位標籤；
- 白色內容文字。

編輯器把 `font-size` 套在外層 section，但正式 CSS 又直接指定內層 `small` 與 `p` 的字級，因此內層規則覆蓋外層設定。使用者看到右側字級數值改變，左側真正文字卻沒有變。

同一個外框也讓標籤、正文與背景只能一起移動或縮放，不符合使用者期待的 PPT 式精細調整。

## 2. 已確認的產品決策

採用方向 A：七頁所有可見文字依「邏輯文字層」拆成獨立版面元素。

「獨立」是指每一個有不同排版角色的文字層都能分別調整：

- X／Y 位置；
- 寬度與高度；
- 字級；
- 靠左、置中或靠右。

不把每個換行或每個字拆成元素。一段標題仍是一個文字層；只是標籤、標題、正文不再共用同一個版面框。

模板編輯器只調版面，不修改實際文案。動態內容仍由既有七頁內容編輯器修改；固定的模板提示文字也不在模板編輯器改字。

## 3. 使用者結果

以第二頁「基本資料」為例，畫布上將有四個互相獨立的元素：

1. `facts-bg`：深藍背景；
2. `facts-label`：橘色「基本資料」；
3. `facts-body`：白色內容文字；
4. 其他元素不會因其中一個被移動而跟著改變。

調整 `facts-body` 字級時，真正顯示的白色文字立即改變；選取框尺寸與真正文字層一致。

## 4. 拆層原則

### 4.1 文字

- 每個可見且具有獨立字體角色的文字，必須有自己的 `data-layout-id`。
- `font-size` 與 `text-align` 直接套在承載文字的元素，不套在父層容器等待繼承。
- 動態文字的 `data-edit-key` 與版面元素放在同一節點，避免內容編輯與模板編輯指向不同 DOM。
- 固定提示字雖不可改文案，仍可作為文字層調整排版。

### 4.2 背景與裝飾

- 色塊、線條、軸線與卡片背景是獨立的非文字元素。
- Logo、機器人與表情圖示是獨立圖像元素。
- 移動文字不帶動背景；移動背景也不帶動文字。
- 背景元素維持 `collision="background"`，不因與其上的文字重疊而被判定為錯誤。

### 4.3 群組

本輪不新增群組移動。使用者要調整的核心是每層可獨立控制；若同時移動多層，仍逐一處理。多選與群組屬於後續功能。

## 6. 技術結構

```text
舊版 layout JSON（schema v1）
        │ 讀取時正規化，不改資料庫舊列
        ▼
layout schema v2：獨立文字／背景／圖像元素
        │
        ├── 正式 Renderer：每個元素輸出唯一 data-layout-id
        │
        └── 模板編輯器：白名單屬性直接套到該 DOM 節點
                    │
                    ▼
              儲存為新的 vN 版本
```

### 6.1 Layout schema v2

- 新的內建版面使用 `schema_version = 2`。
- v2 registry 列出所有獨立元素及其種類、最小尺寸、字級上下限與碰撞政策。
- parser 繼續拒絕未知元素、未知屬性、非有限數字、越界尺寸與不支援的對齊方式。

### 6.2 舊版本相容

- 資料庫內既有 v1、v2 模板版本保持不可變，不原地 rewrite `layout_json`。
- 讀取 schema v1 時，先用舊 composite 元素的位置，配合內建 v15.1 子層預設幾何，轉成記憶體中的 schema v2 layout。
- 使用者開啟舊版本時可看到完整新文字層。
- 使用者儲存才建立新的 schema v2 模板版本。
- 既有貼文綁定舊 version ID 時，Renderer 走同一個正規化流程，因此畫面維持原版視覺，不需改 binding。

### 6.3 Renderer

- 不再讓一個 `data-layout-id` 同時承擔背景、標籤與正文。
- 版面 CSS 只由 layout document 對獨立元素設定幾何與文字樣式。
- 品牌 CSS 仍負責顏色、字重、行高與裝飾，但不得用固定 `font-size` 覆蓋 layout text element。
- 若品牌 CSS 需要不同層級的預設字級，數值放入內建 v2 layout，不放在會覆蓋使用者設定的 selector。

### 6.4 模板編輯器

- property panel 的字級變更直接更新實際文字節點。
- 拖曳、縮放、鍵盤方向鍵、復原、重做與 Escape 都沿用既有 working layout 流程。
- 選取背景只顯示 X／Y／寬高；選取文字才顯示字級與對齊。
- 若 Renderer 少任何 registry hook，顯示同步錯誤並禁止儲存。

## 7. 資料與安全

- 不新增外部相依、CDN、LLM 或付費服務。
- 不提供任意 CSS、HTML、JavaScript、URL 或本機路徑輸入。
- 只接受 registry 內元素與白名單屬性。
- 不修改 carousel 內容 schema。
- 正式資料驗收使用 SQLite backup；正式畫面驗收不按儲存，除非另有明確測試版本流程。

## 8. 錯誤處理

- 舊 schema 無法正規化：顯示可理解錯誤並禁止儲存，不靜默丟棄元素。
- 預覽缺少 hook：列出缺少的元素並禁止儲存。
- 文字超出自身框或畫布：沿用 Chromium 精準驗證，拒絕建立新版本。
- 拆層後發生非法碰撞：指出具體元素標籤，讓使用者回畫布修正。

## 9. TDD 與驗收

採垂直 Red → Green → Refactor：

1. 先用瀏覽器重現第二頁 `facts` 字級數值改變但內層 `p` 計算字級不變。
2. 拆出第二頁 `facts-bg`、`facts-label`、`facts-body`，讓單一案例轉綠。
3. 驗證只移動 label 時，body 與 background 的 bounding box 不變。
4. 逐頁增加獨立元素 registry、內建 layout 與 Renderer hook；每次只處理一頁並讓該頁契約轉綠。
5. 補 v1 → v2 正規化測試，確認舊版畫面幾何與拆層前一致，且資料庫舊 JSON 未改。
6. 補儲存／重開測試，確認 schema v2 新版本可完整 round-trip。
7. 三家公司、七頁、桌機與手機跑 overflow／碰撞壓力測試。
8. 完整測試、兩輪視覺 QA、合併 main 後再跑全套，最後驗證正式站核心流程。

### 必須量測的使用者結果

- 字級欄位增加後，實際文字的 computed `font-size` 同步增加。
- 選取框與實際文字層的邊界差不超過 1 CSS px。
- 移動任何單一文字層時，未選取的同區背景與文字位移為 0。
- 七頁所有可見文字都能對應到一個文字 registry element。
- 正式 Renderer 與模板預覽使用同一份 layout。
- 375px 無橫向捲動，手機沒有儲存操作。

## 10. 非目標

- 多選、群組、鎖定／解鎖、圖層面板與 z-order；
- 新增、刪除或複製元素；
- 旋轉；
- 自訂字型、色票或任意 CSS；
- 在模板編輯器修改動態內容；
- 改變七頁內容結構或重新設計貼文視覺。

## 11. 完成定義

- 第二頁截圖中的「基本資料」背景、標籤與正文可獨立選取及調整。
- 七頁所有可見文字完成相同拆層。
- 字級、位置、尺寸與對齊即時反映在真正內容。
- v1 layout 能無資料破壞地正規化至 v2；新儲存版本為 schema v2。
- 聚焦測試、全套測試、跨公司壓力測試及兩輪視覺 QA 全部通過。
- `HANDOFF.md` 記錄測試數據、截圖路徑、剩餘限制與正式站驗收。
