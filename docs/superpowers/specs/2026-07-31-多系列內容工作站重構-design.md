# 多系列內容工作站重構 — 設計規格

> 日期：2026-07-31  
> 狀態：使用者已核可 A1「今日下一步＋所有內容系列」，並要求五項改善直接實作。

## 1. 目標

把目前將所有功能垂直堆疊的「選題工作台」，改成隨時回答三個問題的內容工作站：

1. 我正在處理哪個內容系列？
2. 這個系列目前做到哪一步？
3. 下一個明確動作是什麼？

資料表、LLM、搜尋、來源驗證、Logo 規則與輪播出圖引擎維持不變。本輪只重構
資訊架構、呈現方式、操作連續性與品牌回饋。

## 2. 已核可的產品模型

- UI 全面把 `Theme` 稱為「內容系列」，但資料庫欄位與 Python 類別不做破壞性改名。
- AI 新創介紹只是第一個系列；之後可新增任意系列，每個系列保有自己的提醒日、來源、
  候選、採用內容、輪播與已發紀錄。
- 首頁採 A1：最上方顯示跨系列的「今日下一步」，下方顯示所有內容系列。
- 進入系列後固定走四步驟：`找題材 → 選一則 → 寫內容 → 做輪播`。
- 系統預設自動搜尋可信網域、驗證內容並產生草稿；人工來源是補漏，不是必經主路徑。

## 3. 資訊架構

### 3.1 主導覽

- `工作台`：今日下一步、所有內容系列、待辦概況。
- `內容製作`：選定系列後的四步驟工作區。
- `成效`：已發內容與系列表現。
- `系統設定`：API provider、model 等系統層設定。

### 3.2 工作台

- 一張主任務區：角色指出目前最值得處理的一件事，只有一個 primary CTA。
- 內容系列以可掃讀的列／小卡顯示名稱、提醒日、來源數、目前步驟與待處理數。
- 「新增內容系列」是獨立入口；新增時一次設定名稱、提醒日、產生數與素材來源。
- 週行事曆、成效表與 API 提醒降到次要區域，不與主任務競爭。

### 3.3 系列工作區

- 頂部固定顯示系列名、四步驟與完成狀態。
- 系列名稱／提醒日／來源綁定放進「管理內容系列」，不再與每日工作並排。
- 每一步只顯示該步驟必要的內容與一個主要動作。
- 手機以單欄顯示；步驟列可換行但不得產生橫向捲動。

## 4. 四步驟行為

### 4.1 找題材

- 顯示目前系列使用幾個可信來源及既有候選狀態。
- 沒有候選時 primary CTA 是「開始找題材」。
- 已有候選時產生按鈕降級為「再產生 N 則」，primary CTA 改為「查看候選」。
- 沒有綁來源時明說系統會只依系列名稱發想，並提供管理來源入口。

### 4.2 選一則

- 左側是緊湊候選清單，只顯示公司、標題與一句角度。
- 右側只呈現目前選中的候選完整內容、查證入口及採用／微調／淘汰。
- 採用後設定選中內容並立即切到「寫內容」；toast 只做確認，不承擔導覽。
- 淘汰保留一步完成與最後一筆復原。

### 4.3 寫內容

- 若有多則採用內容，先用緊湊選擇器選一則。
- 顯示正文、平台字數、儲存狀態；主要動作是「儲存並繼續做輪播」。
- `退回候選` 與 `標記已發` 為次要／完成動作；disabled 時就地說明原因。

### 4.4 做輪播

- 顯示線性 readiness checklist：公司名稱、這篇內容的查證證據、官方 Logo、
  七頁草稿、七張圖片。
- 每列顯示 `完成／需要處理／等待前一步` 與唯一對應動作。
- 預設主路徑為「自動查證並產生草稿」；手動補來源、重新查證與重新產生放入進階區。
- 有圖片後最高層級動作是「下載全部（ZIP）」。

## 5. 品牌與視覺

方向為「編輯式 AI 實驗室」，但仍是高頻工作工具：

- 沿用品牌藍、淺藍、暖橘與既有深／淺模式，不採 AI 紫粉色。
- 吉祥物擔任任務教練：`point` 指下一步、`think` 陪伴判斷、`note` 表示編寫／查證、
  `happy` 表示完成、`confused` 表示可復原錯誤。
- 角色只出現在主任務、空狀態、載入／錯誤／完成，不在每張卡重複貼圖。
- 移除 `RADAR`、單側彩色粗邊框、無意義英文眉標與等權卡片網格。
- 以完整輪廓、留白、字重與語意狀態建立層級；不用大陰影、玻璃效果或裝飾性漸層。
- 按鈕只做 160ms press／hover 回饋，所有位移尊重 `prefers-reduced-motion`。

## 6. 名稱與層級

| 舊名稱 | 新名稱 |
|---|---|
| 概覽 | 工作台 |
| 選題 | 內容製作 |
| 設定 | 系統設定 |
| 主題 | 內容系列 |
| 來源庫 | 素材來源庫 |
| 這個主題抓哪些來源 | 系列素材來源 |
| 已查證來源／來源快照 | 這篇內容的查證證據 |
| 產生候選 | 開始找題材／再產生 N 則 |

每個畫面最多一個 primary CTA；危險操作與復原保留文字，不只靠顏色區分。

## 7. 技術邊界

- 新增 `daibu/workspace.py`，集中四步驟、今日任務與輪播 checklist 的純函式。
- `daibu/overview.py` 只負責工作台資料組合與 Streamlit 渲染。
- `pages/1_選題.py` 保留既有服務呼叫，但依 active step 做漸進揭露。
- `daibu/ui.py` 提供角色教練、步驟列與狀態 HTML；`daibu/theme.py` 只管 token/CSS。
- 不新增資料表，不改 API，不呼叫付費服務；驗收只用 `/tmp` 資料庫。

## 8. 錯誤與資料安全

- 產生候選、查證、產草稿與產圖失敗時，保留既有資料並在當步提供重試。
- 刪除系列／來源仍需確認；淘汰仍可復原。
- 切換步驟不寫 DB，只更新 `st.session_state`。
- 真實 `daibu.db` 不用於測試或瀏覽器操作。

## 9. 驗收

- 工作台第一屏能看見今日下一步與全部內容系列。
- 內容製作頁能在四步驟間切換，且採用後直接進入寫內容。
- 候選不再全部展開成重複大卡；一次只閱讀一則完整候選。
- 輪播以五列 checklist 呈現依賴，disabled 動作有原因。
- 桌機 1280×800、手機 375×812 無橫向捲動、穿模或遮擋。
- heading 順序完整，重複動作含內容標題，文字對比 ≥4.5:1。
- 兩輪視覺自檢、相關測試與全套測試通過，真實 DB mtime 不變。

## 10. 不做

- 不改資料庫 schema 或把 `Theme` 類別真的重新命名。
- 不新增社群平台文案產生器、登入、雲端部署或自動發布。
- 不重做輪播 PNG 的 1080×1350 版型；本輪重做的是工作站前端。
