# 建造故事 HTML 改版設計

> 日期：2026-08-06
> 前一版：`docs/superpowers/specs/2026-08-05-社團建造故事-html-design.md`
> 目標檔案：`docs/2026-08-07-呆一布內容工作站是怎麼做出來的.html`（覆寫，不另建新檔）
> 決策來源：2026-08-06 grill-me 對談，十個分岔逐題拍板

## 1. 為什麼改版

使用者的回饋是「內容不對、看起來不好看」。逐項查證後，問題如下。

### 內容

| 問題 | 證據 |
|---|---|
| 是方法論教材，不是建造故事 | 八章裡五章在講抽象方法（分工、系統地圖、測試方法、建造公式），只有「踩坑」有真實質地 |
| 具體素材全在別的檔案 | `docs/2026-08-01-社團報告提綱.md` 有 Warp、478 字正文、3 筆查證來源、449 項測試、BillionToOne；HTML 裡只剩 99／24／4 |
| 零張成品圖 | 一篇「我怎麼搭出這工具」的文章，沒有任何工具截圖或輪播成品 |
| 原則無法落地 | 「先寫一個真實痛點」「拆成小切片」這類句子，讀者點頭但回到電腦前仍不知道第一步要做什麼 |

### 視覺

| 問題 | 證據 |
|---|---|
| 整頁沒有深色錨點 | 底 `#E9F6FF`、卡片 `#FAFCFE`、邊框 `#C7E2EA`、主色 `#6FC1CC`，全在最淡的幾階；品牌其實有 `#244A5B`、`#315F73`、`#4F5362`，一個都沒用上 |
| 全篇是等大卡片網格 | 三欄卡、六格卡、五張卡、八步卡。前一版設計文件第 4 節明寫「不把所有內容切成等大的卡片網格」，實作未遵守 |
| 貼文配色直接當長文底色 | `#E9F6FF` 一系來自輪播模板 `daibu/cards/templates/ai-startup.css`，那是設計來當大色塊背景、配少量短字的 |
| 首屏空轉 | 桌機與手機首屏都被巨大標題與吉祥物卡堆佔滿，沒有任何實質資訊 |
| 吉祥物重複出現 | 吉祥物已經出現在輪播成品圖裡（`03-problem.png` 內有三個），頁面再放一次是重複 |

## 2. 產品結果

一份繁體中文單頁 HTML，主要工作是**教學**：讓讀者能照著做，並理解這個系統怎麼運作。

讀者讀完要能回答：

1. 一個功能從「我想要」到「產出檔案」中間實際發生了哪些事。
2. 這中間六個系統角色各自在哪一步發揮作用。
3. 怎麼確保 AI 不會一次寫歪，以及為什麼測試全綠不代表沒問題。
4. 自己要做類似工具時，第一步做什麼。

## 3. 十個拍板決策

| # | 分岔 | 決定 |
|---|---|---|
| 1 | 這篇的工作 | 教學：讓人照著做 ＋ 解釋系統怎麼運作 |

| 7 | 工具定位 | 通用架構，目前一個系列 |
| 8 | 品牌關係 | 同一組色，把深色階拉回來當結構色 |

| 10 | 落檔方式 | 覆寫同一份，舊版留在 git |

## 4. 章節結構

### 第一章：一個功能從發想到出圖（主線）

以 2026-07-28 那晚的輪播圖產生器為敘事骨幹，約 70 分鐘的完整弧線：

1. 起念——每次介紹一家公司都要在搜尋、筆記、文案、做圖之間切換。
2. 看參考、定調性。
3. **喊停，先對齊內容範圍**。原本的七個頁型裡有「文組生用途」「多少錢」，先砍掉，因為這個系列介紹的是公司與他們怎麼用 AI。
4. 選出圖技術：Playwright。
5. 配色與字體的取捨，包含「先用這個，之後再改」這種暫時決定。
6. 拍板、寫計畫、施工。
7. 收尾放**七張 Railway 輪播成品**。

這一章吸收掉舊版的「起點」「分工」「時間軸」三章——主線本身就有起點、有分工、有時間順序。

不放任何對話原文。轉述時用第一人稱敘事，不加引號、不標時間戳。

### 第二章：這中間系統做了什麼

六個角色（Streamlit、Python、SQLite、RSS／Tavily、Gemini、Playwright）**掛在第一章的主線上講**，不再是六張並排的名詞卡。

寫法是沿著主線的時間軸標出每一步由誰負責：草稿存進哪裡、文字由誰生成、圖由誰拍。名詞第一次出現仍用「白話 → 定義 → 在這個產品裡負責什麼」三層，但收進 `details` 展開區，不打斷主文。

### 第三章：我怎麼確保它沒寫歪

合併舊版的「測試方法」與「踩坑」兩章。

核心用 `ia-refactor` 那組修前／修後對照（已驗證差異可讀）：

| | 修之前 | 修之後 |
|---|---|---|
| 側邊欄第一項 | `app` | 概覽 |
| 三張數字卡 | 兩個橘色小圓圈＋一個大數字，樣式不一致 | 一致的大數字 2／1／0 |
| 第三張標籤 | 已發 | 本週已發 |
| 右上角 | 無障礙圖示、Stop、Deploy、⋮ | 只剩 Deploy |

側邊欄那個 `app` 是重點：那是 Streamlit 直接把檔名當成選單標籤，自動測試不會抓到，只有真的打開來看才會發現。這是「99 個測試全綠、真人操作仍找出 24 個問題，其中 4 個會弄壞資料」最好的具體長相。

TDD 的 Red → Green → Refactor 保留，但綁在主線的一個實際修正上，不再用抽象的煙霧警報器比喻獨立成段。Mock 與契約測試的差異保留，壓縮成一段。

### 第四章：你可以照這個順序做

舊版的八步公式保留，但每一步改成回指第一章主線裡對應的那個時刻，讓原則有具體出處。

## 6. 視覺方向

### 配色

沿用呆一布品牌色，但把深色階拉回來當結構色。

| 角色 | 色票 | 用在哪 |
|---|---|---|
| 結構深色 | `#244A5B` | 章節頭、拉引句、頁首頁尾、重點區塊底 |
| 次深色 | `#315F73` | 副標、連結、圖說 |
| 強調色 | `#6FC1CC` | 單一強調，用量克制 |
| 點綴 | `#F8C0A0` | 只在極少數需要跳出的地方 |
| 頁面底 | 接近白的暖底，`#E9F6FF` 退成少數區塊底而非全頁底 | |
| 內文 | `#0E0E2C` | |

原則：全頁主要顏色不超過三個，灰階要有層次。

### 字體

編輯式雜誌配對：

- 標題：思源宋體（Noto Serif TC）
- 內文：思源黑體（Noto Sans TC），中文內文至少 16px
- 數字與標籤：JetBrains Mono，用在 `1080×1350`、`449`、`round1／round2` 這類值

標題與內文至少差兩級大小與字重。

### 骨架

編輯式雜誌：非對稱格線、大圖橫跨版面、拉引句、章節分隔線。**不使用等大卡片網格**——這是前一版失守的地方，實作時逐章檢查。

七張成品與修前／修後對照都用大圖呈現，對照組左右並排（手機改上下堆疊）。

### 首屏

**維持現狀**（標題 ＋ 吉祥物）。不放 Railway 封面圖當主視覺——那會把工具誤框成「AI 新創介紹產生器」。首屏引言改寫成「通用架構，目前跑一個系列」的定位。

正文裡的七張圖介紹成「第一個系列的產出」，不是「這個工具做的東西」。

## 7. 工具定位的準確寫法

程式現況（已查證）：

- `daibu/seeds.py:16` 的 `DEFAULT_THEMES` 只有一個系列「AI 新創介紹」
- `db.add_theme()` 只有 `seeds.py` 呼叫，介面上沒有新增系列的入口
- `pages/3_設定.py` 全長 83 行，只處理 Tavily 與系統設定
- 資料模型是多系列的：`themes` 表、`content_kind` 有 `general` 與 `company_profile`、首頁有「我的內容系列」清單

因此文章的寫法是：一個內容工作站，架構上可以跑不同的內容系列；目前先把「AI 新創介紹」這一條路走通。**不可**寫成「已經能產出多種內容」。

## 7.5 主線每個說法的出處（必讀）

第一版的第一章是憑「這個功能為什麼要做」反推出來的動機，不是查證過的事實。使用者指出「這個根本沒有」之後全章重寫。**之後任何改寫都必須對得上下表，不能憑印象補。**

| 文中的說法 | 出處 |
|---|---|
| 當時正文是使用者自己手打的，AI 只產標題候選，圖完全沒碰 | `docs/specs/2026-07-28-貼文輪播圖產生器-design.md` §1 現況 |
| 卡住的是「圖片生成服務多數付費」與「只用免費額度」牴觸，導致連設計都無法開始 | `docs/open-questions.md:67`（已結案 2026-07-28） |
| 解法是想通「圖是文字圖卡＝網頁排版後截圖」，吉祥物是模板的一部分 | 同上 §1「這條衝突已解除」 |
| 頁型原本有「文組生用途」「多少錢」，改掉 | 2026-07-28 逐字稿 18:02；spec §4.1 |
| 「AI 新創介紹＝介紹一家具體公司以及他們如何運用 AI」，不談定價 | spec §4.1 |
| 喊停對齊花了快二十分鐘 | 逐字稿 17:41 → 17:59 |
| 出圖三選項與否決理由（Pillow 要自己算座標／html2canvas 預覽好看匯出走樣） | spec §5，Playwright 段的備援選項表 |
| 選 Playwright 的理由是「匯出必須跟預覽一模一樣」 | spec 決策表 #12 |
| 不要薄荷綠 `#C3DDD3` | 逐字稿 18:04–18:05 |
| 字體先用芫荽 Iansui 當暫定，同日改成 LINE Seed TW | spec §字體段與決策表 #15、#17 |
| 整段約 70 分鐘 | 逐字稿 17:09 → 18:22 |
| 24 條問題、99 個測試、正文 134 字消失 | `docs/history/HANDOFF-2026-07-26-qa-fixes.md` |

`tests/test_build_story_html.py` 用 `test_story_keeps_tech_notes_and_removed_features` 守住其中幾個數字，但**大部分說法沒有辦法用測試防守**，只能靠這張表。

## 8. 不做什麼

- 不放任何對話原文、不放時間戳、不放截圖裡的聊天畫面。
- 不新增「新增內容系列」功能（已另開背景任務追蹤 `daibu/overview.py:112` 指向不存在入口的問題）。
- 不改公開網址、不另建第二份 HTML。
- 不引入 build 流程，維持單檔 HTML ＋ Tailwind CDN。
- 不做深色模式（前一版也沒有，範圍不擴大）。

## 9. 驗收標準

1. 全篇找不到任何逐字引用的對話原文。
2. 七張 Railway 成品與至少一組 `ia-refactor` 修前／修後對照確實嵌入且在 375px 寬可讀。
3. 章節數為四。
4. 頁面出現 `#244A5B` 或 `#315F73` 作為主要結構色，且不是只用在內文字。
5. 全篇沒有任何三欄以上的等大卡片網格。
6. 首屏引言明確寫出「架構可跑多系列、目前一個系列」。
7. 桌機 1280×800 與手機 375×812 截圖自檢兩輪通過，375px 無橫向捲動。
8. `tests/test_build_story_html.py` 同步更新並全綠。
