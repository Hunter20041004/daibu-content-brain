# 呆一布內容工作站 Demo 影片設計

日期：2026-08-01

## 目標

製作一支約兩分鐘、16:9 的自動操作示範影片，讓非技術背景的社團成員看懂目前工作站已能完成的內容流程。影片以功能導覽為主，不講開發歷史；使用者在現場自行口頭報告，因此影片只放短字幕，不加配音。

同時整理一份 3–5 分鐘口頭報告提綱，內容與影片順序一致。

## 核心訊息

呆一布內容工作站已能把「找一家值得介紹的 AI 新創」一路接到「可下載的七張社群輪播圖」，並在流程中保留人工採用、來源查證與官方 Logo 確認。

## 影片結構

| 時間 | 畫面與操作 | 字幕目的 |
|---|---|---|
| 0:00–0:03 | 標題「呆一布內容工作站｜從找公司到七張輪播」 | 只交代主題 |
| 0:03–0:18 | 進入 AI 新創介紹並啟動 AI 找公司 | 說明正在搜尋可信網域 |
| 0:18–0:38 | 展示候選公司與一句話介紹 | 強調候選是具體公司 |
| 0:38–1:00 | 採用公司並產生正文初稿 | 強調人做決定、AI 協助起稿 |
| 1:00–1:20 | 展示查證來源與官方 Logo 流程 | 強調資料可信度與品牌來源 |
| 1:20–1:50 | 展示七張輪播內容與圖片預覽 | 呈現從草稿到成品 |
| 1:50–2:05 | 下載成果並列出目前完成能力 | 收束完整工作流 |

影片可落在 1:50–2:15；標題維持 3 秒。搜尋與生成的真實等待會剪短或加速，只保留能讓觀眾理解狀態的片段。

## 錄製方式與資料流

1. 在 port 8502 操作本機 Streamlit 工作站。
2. 使用 `/tmp` 的 SQLite 資料庫複本，禁止修改真實 `daibu.db`。
3. 真實呼叫 Tavily 與 Gemini，產生新的公司候選。
4. 由介面採用一家公司、產生正文，接著展示來源、Logo、七張輪播與下載。
5. 錄製原始操作畫面後剪掉等待，疊加步驟字幕，輸出 MP4。

資料流為：可信網域搜尋 → AI 整理公司候選 → 人工採用 → AI 正文初稿 → 來源與 Logo → 七張輪播 → PNG／ZIP。

## 安全、錯誤與備援

- 畫面不得顯示 Tavily、Gemini 或其他 API key。
- Logo 只能來自公司官網或官方品牌素材；新 Logo 必須先由使用者確認，不能用圖片搜尋的第一張代替。
- Tavily 或 Gemini 失敗時只重試一次。若仍失敗，保留真實搜尋片段，後段改接既有完整案例，並以字幕清楚標示轉場。
- 若新公司缺少可驗證 Logo，影片先停在 Logo 前等待使用者確認，不繞過規則。
- 不更動產品程式碼；若錄影揭露 bug，只記錄，不在本工作項目順手修正。

## 口頭報告提綱

3–5 分鐘報告依影片順序說明：這是什麼、六個主要功能、現在已完成到哪裡、目前限制與下一步。用產品能力與使用者結果描述，不逐項講技術實作。

## 驗收

- MP4 為 16:9，建議 1280×720 或 1920×1080。
- 標題約 3 秒；總長 1:50–2:15。
- 完整呈現找公司、候選、採用、正文、來源／Logo、七張輪播與下載。
- 字幕簡短、可讀，沒有遮住主要按鈕或內容。
- 沒有金鑰或其他祕密出現在影像。
- 真實 `daibu.db` 的修改時間在錄製前後一致。
- 另有一份可直接照著講的 3–5 分鐘繁體中文提綱。
