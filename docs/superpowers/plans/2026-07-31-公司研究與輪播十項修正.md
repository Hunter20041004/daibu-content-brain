# 公司研究與輪播十項修正 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓輪播草稿先從可信網域補齊並驗證公司資料，再以可逐字回指的證據一次產生七頁，並修完 2026-07-30 驗收的十項問題。

**Architecture:** 新增獨立的 `company_research` 管線負責白名單搜尋、正文擷取、公司相關性與來源類別；草稿層改為單次 Gemini 結構化輸出與原文引句核對。新來源包、來源快照與草稿以 SQLite 同一個 transaction 寫入；預覽、出圖與子頁 reload 問題在各自邊界修正。

**Tech Stack:** Python 3.11+、Streamlit 1.60、SQLite、pytest、Tavily、Google Gemini structured output、Playwright、Starlette routes。

## Global Constraints

- 固定使用免費 provider；預設 Gemini Flash，備援 Groq，不得使用 Claude 或付費模型。
- Tavily 每次搜尋必須傳 `include_domains`；回傳結果再做一次 hostname 白名單過濾。
- Logo 只能來自公司官網或官方品牌素材，不新增圖片搜尋。
- 任何失敗不得覆蓋現有來源包、快照、草稿、Logo、圖片或題目狀態。
- 公開證據不足就少寫並明說限制；140–220 字是目標，不是強迫補造事實的下限。
- 使用者決定是否發布；產品只呈現證據、可讀性與規格問題。
- 手動驗收只使用 `/tmp/daibu-test.db`、port 8502；只截 1280×800 與 375×812 各一張；真實 `daibu.db` mtime 必須不變。
