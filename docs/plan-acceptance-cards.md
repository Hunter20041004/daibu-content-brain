# 輪播圖全流程操作驗收腳本（2026-07-30）

> 這不是 TDD 實作計畫，是一份**操作腳本**：照著跑、逐項記錄、回報問題清單。
> 執行者：Codex。設計依據：`docs/specs/2026-07-30-來源蒐集與出圖接線-design.md` §10。

## 為什麼要做這一輪

349 個測試全綠，但**全部都是程式在驗程式**。上一次真人操作驗收（2026-07-25）也是
在 99 個測試全綠的情況下，揪出 24 條問題、其中 4 條會弄壞資料——它們的共同點是
跨越了單一函式的邊界。這一輪要用**真實資料、真實網路、真實 AI 額度**走完一次。

## Codex 做什麼、不做什麼

| 做 | 不做 |
|---|---|
| 走完整流程，記錄每一步的實際行為 | **不判斷「這則內容值不值得發」**——那是使用者的產品決策 |
| 以觀眾視角逐張檢視七張圖，指出讀不懂／不通順／違反規格之處 | 不改內容去迎合自己的審美 |
| 發現問題就記錄並繼續往下走 | 不順手修 bug——這一輪只驗收，修正另開一輪 |
| 需要使用者拍板時停下來問 | 不替使用者決定用哪家公司、哪張 Logo |

**例外**：流程被完全擋死、無法繼續時，才可以做最小修正讓流程走下去，並在報告中
明確標示「這裡我改了什麼、為什麼非改不可」。

## 前置

### 0-1 用複本，不要碰真實資料庫

```bash
cp daibu.db /tmp/daibu-test.db
DAIBU_DB_PATH=/tmp/daibu-test.db .venv/bin/streamlit run app.py --server.port 8502
```

使用者自己常開著一個 Streamlit 在 8501，**一定要挑別的 port**。

### 0-2 先確認舊資料庫能不能升級（這一步很重要）

使用者的真實 `daibu.db` **還停在很舊的結構**：`ideas` 只有
`id / theme_id / title / angle / source_url / status / body / created_at /
published_at`，**沒有 `company`、沒有 `source_excerpt`**，也沒有
`carousel_pages`、`carousel_sources`、`idea_sources`、`brand_assets` 任何一張表。
裡面有 3 個主題、8 則題目（6 候選、1 採用、1 已發）。

所以複本第一次被新版開啟時，會實際跑一次**從舊結構到新結構的搬遷**。要記錄：

- [ ] App 有沒有正常起來、有沒有紅色例外
- [ ] 3 個主題、8 則題目是不是**一則都沒少**，狀態有沒有跑掉
- [ ] `PRAGMA table_info(ideas)` 有沒有補上 `company` 與 `source_excerpt`
- [ ] 四張新表是不是都建起來了

這是整個腳本裡最可能出事、也最沒被測試涵蓋的一步——單元測試用的是乾淨的
`tmp_path` 資料庫，不是使用者用了好幾週的這一份。

## A. 操作驗收

依設計規格 §10.1 的七條驗收條件，**逐條記錄「符合／不符合＋證據」**。

### A-1 產一批新候選（會花免費額度）

舊的 6 則候選是用**舊 prompt** 產的，沒有公司名也沒有原文引文，接不上輪播流程。
到「AI 新創介紹」主題按「產生候選」，產一批新的。

- [ ] 產得出來、沒有紅色例外
- [ ] 新候選**帶得出具體公司名**與 60 字以上的原文引文
- [ ] 記錄實際等待秒數

若免費額度當天已用盡，記錄錯誤訊息是否看得懂（規格要求 429 要轉成產品錯誤），
然後改用手動方式：採用一則舊候選並手動填公司名，繼續往下跑。

### A-2 採用一則，檢查「資料未齊」狀態

採用一則有公司名的候選，展開它的「輪播圖」區塊。

- [ ] 缺什麼講得清楚（例如「還沒有任何已查證來源」）
- [ ] 每一條缺件旁邊就有能立刻補的入口，不用跑去別的頁面
- [ ] 另外展開一則**舊的**已採用題目（沒有公司名那則），確認它顯示
      「這則題目還沒有公司名」且不會炸

### A-3 蒐集來源

貼一個真實的公開 https 網址（該公司的官網說明頁或一篇報導），按「抓取內容」。

- [ ] 出版方／日期／引文有沒有帶出建議值
- [ ] 建議值**對不對**（尤其日期，抓錯比抓不到更危險）
- [ ] 抓不到時錯誤訊息看不看得懂，**已填的欄位有沒有被清空**
- [ ] 存成第一筆來源，確認顯示為 `S1`
- [ ] 再加 2–3 筆（至少一筆來自不同網站），確認編號依序
- [ ] 刪掉中間一筆，確認**其他筆的編號沒有跟著變**
- [ ] 記錄有沒有網站擋自動抓取，以及擋掉時介面是否還能手動填

### A-4 Logo

Logo 只能來自**公司官網**或**官方品牌素材包／媒體中心**，規格明文禁止從一般圖片
搜尋抓第一張圖。

- [ ] 從官方品牌頁下載 SVG 或去背 PNG，**把來源網址記進「官方來源網址」欄**
- [ ] **下載後把 Logo 貼給使用者確認是不是官方版本**，再繼續（這一步是規格
      要求的「使用者確認」，不可略過）
- [ ] 上傳成功後顯示縮圖、來源網址、確認日期
- [ ] 故意上傳一張**不合格**的圖（例如網站的 favicon，或任何 4096 px 以上的圖），
      確認被擋下、訊息看得懂、畫面不崩、且 `assets/logos/` 底下**沒有留下垃圾檔**
- [ ] 確認「產生輪播草稿」在缺 Logo 時**仍然可按**，「產生七張圖」才不可按

### A-5 產草稿與編輯

- [ ] 按「產生輪播草稿」，記錄實際等待秒數與是否需要修稿回合
- [ ] 七頁都有內容、每頁來源標示正確
- [ ] 把某一頁的文字**改到過短**（違反 140 字下限）後按儲存 → 確認三件事：
      畫面出現錯誤、**輸入框內容還在**、資料庫沒被改
- [ ] 改成合法內容後儲存成功
- [ ] 「重新產生」有二次確認，文案講明會覆蓋

### A-6 出圖與 ZIP

- [ ] 按「產生七張圖」，記錄實際等待秒數
- [ ] 七張縮圖都出得來
- [ ] 下載 ZIP，解開確認是 `01-cover.png` 到 `07-cta.png` 七個檔
- [ ] 改一段草稿文字並儲存 → 確認舊圖失效、要重按才有新圖

### A-7 例行檢查

- [ ] 全程 console **0 errors**
- [ ] 375px 寬度下無橫向捲動、無破版（桌機 1 張、手機 1 張，就這兩張）
- [ ] 真實 `daibu.db` 的修改時間**沒有變**（證明全程跑在複本上）

## B. 觀眾視角檢視七張圖

把七張 PNG 當成一則真的 IG 貼文來看。**不要評「好看／不好看」，回答下面每一題**：

1. 第 1 張能不能在 1 秒內看懂「這是哪家公司、做什麼的」？
2. 第 1 張有沒有給人繼續往下滑的理由？
3. 每一張的**第一行**單獨看得懂嗎？（IG 讀者常常跳著看，不是每張都從頭讀）
4. 有沒有哪一張要重讀第二次才懂？是哪一句卡住？
5. 七張看完，能不能用一句話說出這家公司在幹嘛？
6. 有沒有出現「不學就被取代」這類焦慮話術？（規格明文禁止）
7. 有沒有哪一張是**廢話張**——刪掉也不影響理解？
8. 來源標示看得到嗎？有沒有擠壓到內容？
9. 縮到 IG 實際顯示大小時，最小的字還讀得到嗎？
10. 有沒有出現來源裡根本沒提到的公司、人名、客戶或數字？（這是最嚴重的一種錯）

第 10 題若答「有」，直接標成會弄壞信任的問題，優先處理。

## C. 回報格式

在 `HANDOFF.md` 的本輪狀態寫摘要，完整清單另存
`docs/2026-07-30-輪播全流程驗收回饋.md`，問題分三級：

| 等級 | 意思 |
|---|---|
| 🔴 會弄壞資料或信任 | 資料遺失、狀態跑掉、內容出現來源沒有的事實 |
| 🟠 會擋住流程 | 做不下去、必須繞路、錯誤訊息看不懂 |
| 🟡 礙眼但不擋 | 版面、文案、順手度 |

每條寫：**發生什麼 → 怎麼重現 → 期待的行為**。不要在這一輪順手修。

## D. 分支清理（使用者已同意）

先存一份現況再動手：

```bash
git branch -a -v
```

然後刪除三個已無用的分支：

```bash
git branch -d codex/carousel-redesign-phase-c
git branch -d codex/ia-topic-first
git branch -D refactor/ia-topic-first
```

- 前兩個**已完全併入 `main`**，用小寫 `-d`；如果 git 拒絕，表示狀況跟預期不符，
  **停下來回報，不要改用 `-D` 硬刪**。
- 第三個（`b6b66bc`）沒有併入 main，是 Claude 越權寫的探路稿、內容早被取代，
  所以要用大寫 `-D`。刪掉後該 commit 會變成 reflog 裡的孤兒（約保留 90 天）。
- **只刪本機分支。不要碰 `origin`**，遠端目前只有 `main` 一個分支。
- 刪完再跑一次 `git branch -a -v`，把刪除前後對照貼進報告。
