# 前端品牌重構 — 設計規格

> 撰寫：Claude（🧠 規劃），2026-07-24
> 對象：🖐 Codex（實作）與使用者（產品決策）
> 上游依據：Figma 檔「DIVE web」（呆一布品牌網站設計稿）

## 1. 這份文件在做什麼

把「呆一布選題大腦」（內部工具）的前端，改成與同品牌的對外網站 **DIVE web** 同一套視覺語言，
並在過程中把四個頁面的版面重排成真正好用的操作介面。

**後端邏輯一行都不動**：`daibu/` 底下的 `db`、`selection`、`pipeline`、`performance`、`seeds`、`llm/`、`fetch/`
全部維持現狀。這次只動 `app.py`、`pages/`、`daibu/ui.py`、`.streamlit/config.toml`，並新增 `daibu/theme.py` 與 `assets/`。

## 2. 決策紀錄（2026-07-24 與使用者確認）

| 議題 | 決定 | 理由 |
| --- | --- | --- |
| 字型 | **不使用 LINE Seed TW，改用免費替代字** | 使用者選擇；避免把字型檔放進 repo |
| 深色模式 | **淺色／深色雙模式都做** | 使用者選擇；Streamlit 1.60 原生支援 `[theme.light]` / `[theme.dark]`，不會有「一半元件不跟著換」的碎裂問題 |
| 重構深度 | **換皮 + 版面重排** | 只換皮無法解決「每頁都是一堆表單疊在一起」的問題；資訊架構（四頁分法）維持不變 |
| 品牌資產 | **由 Claude 依設計稿重繪吉祥物 SVG** | 使用者未登入 Figma 匯出；已交付 `assets/mascot.svg` |

## 4. Design Tokens（本專案的實作值）

「token（設計代幣）」＝把顏色、字級這些設計決定，寫成有名字的常數，
程式各處只引用名字、不寫死色碼。改一處就全站生效，也才測得動。

### 4.1 顏色 token 與雙模式對照

| Token 名稱 | 淺色模式 | 深色模式 | 用在哪 |
| --- | --- | --- | --- |
| `BRAND_PRIMARY` | `#6FC1CC` | `#6FC1CC` | 主要按鈕底、強調線條、圖表主色 |
| `BRAND_SECONDARY` | `#32738F` | `#6FC1CC` ⚠️ | 次級標題、連結 |
| `INK`（文字） | `#0E0E2C` | `#FAFCFE` | 所有內文與標題 |
| `SURFACE`（卡片底） | `#FAFCFE` | `#171733` | 卡片、側邊欄、輸入框 |
| `CANVAS`（頁面底） | `#E9F6FF` | `#0E0E2C` | 頁面背景 |
| `HIGHLIGHT` | `#F8C0A0` | `#F8C0A0` | 需要注意的狀態：待決策候選數、低守門線警示、下週建議卡 |
| `BORDER` | `#C7E2EA` | `#2A2A4A` | 卡片與輸入框的邊 |

⚠️ **深色模式不得使用 `#32738F` 當文字色**：它在 `#0E0E2C` 上的對比只有 **3.56:1**，低於無障礙標準 4.5:1。
深色模式的次級文字／連結一律改用 `BRAND_PRIMARY`（`#6FC1CC`，對比 9.1:1）。

`SURFACE` 深色值 `#171733` 與 `BORDER` 深色值 `#2A2A4A` 是本規格新增的（設計稿只給了 ONYX），
取值原則：比 `CANVAS` 亮一階、讓卡片浮起來，同時維持 `CLOUD` 文字 16.92:1 的對比。

### 4.2 對比度紅線（實測值，必須寫成測試）

以下數字由 WCAG 相對亮度公式實算，**這是本次重構最容易踩的坑**：

| 組合 | 對比 | 判定 |
| --- | --- | --- |
| ONYX 內文 on 淺色頁面底 `#E9F6FF` | 17.08:1 | ✅ |
| ONYX 內文 on 淺色卡片 `#FAFCFE` | 18.27:1 | ✅ |
| Secondary `#32738F` on 淺色底 | 4.79:1 | ✅ 剛好過 AA |
| **白字 on Primary 按鈕 `#6FC1CC`** | **2.06:1** | ❌ **禁用** |
| **ONYX 字 on Primary 按鈕** | **9.1:1** | ✅ **主要按鈕一律用深色字** |
| ONYX 字 on Highlight `#F8C0A0` | 11.66:1 | ✅ |
| Primary `#6FC1CC` 當文字 on 淺色底 | 1.88:1 | ❌ 只能當底色／裝飾，永遠不能當文字 |
| CLOUD 文字 on 深色卡片 `#171733` | 16.92:1 | ✅ |
| Secondary `#32738F` on 深色底 | 3.56:1 | ❌ 見上 |

**紅線**：所有拿來承載文字的組合，對比必須 ≥ 4.5:1。Streamlit 預設會把 `primaryColor` 的按鈕配白字，
因此 `.streamlit/config.toml` 與 CSS 都必須明確把主要按鈕的文字色壓成 `INK`。

### 4.3 字型

原設計稿使用 LINE Seed TW。本專案採**免費替代方案**：

| 用途 | 字型 | 為什麼選它 |
| --- | --- | --- |
| 英數與標題 | **Figtree**（Google Fonts，字重到 900） | 與 LINE Seed Sans 同為幾何無襯線、雙層 a、字腔緊湊；Poppins 是單層 a 一看就不同，Montserrat 太寬 |
| 中文 | **Noto Sans TC**（Google Fonts，100–900） | 唯一有 ExtraBold(800) 的主流免費繁中字型，才撐得住 Header 的 Extra Bold |

字型堆疊固定為 `"Figtree", "Noto Sans TC", sans-serif`：英數字母由 Figtree 出、中文自動落到 Noto Sans TC。

### 4.4 字級（依工具介面調整）

設計稿的 Title 96px 是行銷首頁的尺寸，內部工具用不上。調整如下（單位 rem，1rem = 16px）：

| 層級 | 值 | 字重 | 字距 | 對應設計稿 |
| --- | --- | --- | --- | --- |
| h1 頁面標題 | 2.5rem (40px) | 800 | 0.04em | Header 1 |
| h2 區塊標題 | 1.75rem (28px) | 800 | 0 | Header 2 縮一階 |
| h3 卡片標題 | 1.375rem (22px) | 700 | 0 | Subtitle 縮一階 |
| h4 | 1.125rem (18px) | 700 | 0 | — |
| h5 / h6 | 1rem / 0.875rem | 600 | 0 | — |
| Body | 1rem (16px)，行高 1.4 | 400 | 0 | Body ✅ 照抄 |

字距 0.04em 只用在 h1（品牌感來源），其餘為 0，避免內文閱讀時鬆散。

### 4.5 圓角與動效

| Token | 值 | 說明 |
| --- | --- | --- |
| `baseRadius` | `16px` | 卡片、輸入框（設計稿卡片圓角偏大） |
| `buttonRadius` | `12px` | 按鈕 |
| `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | 所有 UI 過場 |
| 按鈕過場 | `transform 160ms var(--ease-out)` | |
| 按鈕按下 | `transform: scale(0.97)` | 給「介面聽見了」的即時回饋 |

**動效紅線**（依 `emil-design-eng` 原則）：

- **不做入場動畫**。Streamlit 每次互動都重跑整個腳本，入場動畫會在每次操作後重播，一天看幾十次會非常煩躁。
- 只做 `:hover`、`:active`、`:focus-visible` 三種狀態變化。
- `transition` 一律指名屬性，禁止 `transition: all`。
- hover 效果包在 `@media (hover: hover) and (pointer: fine)` 內。
- 尊重 `@media (prefers-reduced-motion: reduce)`：關閉位移與縮放，保留顏色變化。
- 只動 `transform` 與 `opacity`，不動 `width`／`height`／`padding`。

## 5. 版面重排（逐頁）

共同規則：每頁最上方是 `page_header`（品牌小標 + h1 + 一句話說明），維持現有三段式，但小標改用 `BRAND_SECONDARY` 色。
側邊欄頂端放吉祥物 + 「呆一布 選題大腦」文字標誌。

### 5.1 `app.py` — 今日戰情

現況問題：三個 metric（主題／待決策候選／已發）+ 兩張導引卡 + 五個狀態 metric，資訊平鋪、沒有主次。

改成：

1. **Hero 區**：左側吉祥物（160px）、右側 h1 + 一句話 + **單一主要行動按鈕**「前往本週選題」。
2. **今日焦點列**：三個數字改成以「今天」為主詞 — 今天排定的主題數、待你決策的候選數、本週已發數。
   待決策候選 > 0 時，該數字用 `HIGHLIGHT` 底色的 chip 呈現（這是唯一需要人動作的訊號）。
3. **流水線縮影**：五個狀態改成一條水平進度條（每段寬度依數量比例），下方一行小字標示各段數量。
   取代現在的五個 metric 方塊 —— 五個並排的大數字彼此競爭注意力，但它們其實是一個流程。
4. 底部保留「資料只保存在這台電腦」的說明文字。

### 5.2 `pages/1_選題.py` — 本週選題

現況問題：按鈕、候選卡、微調表單、採用／淘汰全部垂直堆疊，一張卡就佔滿一屏。

改成 **左右分欄（`st.columns([1, 2])`）**：

- **左欄（固定資訊）**：今天排定的主題清單（若無，說明可到設定頁調整）、目前守門線全文、「產生本週選題」主要按鈕、上次產生時間。
- **右欄（候選卡列表）**：每張卡為
  - 左側 **守門線分數視覺化**：不用 `st.metric` 方塊，改成一個圓形或條狀刻度，分數 ≥ 70 用 `BRAND_PRIMARY`，< 70 用 `HIGHLIGHT`（代表「這則要再想想」）。
  - 右側：h3 標題、切入角度（body）、守門理由（caption）、來源連結。
  - 底部一列：`採用`（主要按鈕）、`微調`（展開表單）、`淘汰`（次要按鈕，維持現有的「確認淘汰」勾選才可按，避免誤刪）。
- 空狀態：吉祥物小圖 + 「尚無候選，按左邊的按鈕讓 AI 先整理一輪」。

### 5.3 `pages/2_流水線.py` — 內容流水線

現況問題：五欄看板，但每張卡都內嵌一個含「狀態下拉 + 內容文字區 + 儲存」的表單，欄寬被撐爆、完全無法掃視。

改成 **真正的看板**：

- 五欄，欄頭為狀態名 + 數量 chip（數量用 `BORDER` 底色的小圓角標籤）。
- 卡片極簡：標題（粗體，超過兩行截斷）、主題名 + 守門線分數（caption）。整張卡可點。
- **編輯改用 `st.dialog`**（Streamlit 的彈出視窗）：點卡片開啟對話框，裡面才有狀態下拉、內容編輯區、儲存。
  這樣看板恢復可掃視，編輯也有更大的空間。
- 空欄顯示淡色虛線框 + 「目前沒有內容」，而不是 `st.info` 的藍色方塊。

### 5.4 `pages/3_成效.py` — 成效回顧

改成：

- **回填表單收進頁面右欄**（`st.columns([2, 1])` 的右側）或 `st.expander`，讓「看結果」而不是「填資料」成為頁面主體。
- 左欄主體：主題表現長條圖（顏色用 `theme.chartCategoricalColors`，第一色為 `BRAND_PRIMARY`）+ 明細表。
- **「下週建議」做成一張 `HIGHLIGHT` 底色的卡片**，放在圖表上方 —— 這是整頁最有價值的一句話，現在卻被放在最底下。

## 7. 技術落地

三個檔案各司其職，界線要清楚：

### 7.1 `daibu/theme.py`（新增，純資料 + 純函式，不 import streamlit）

這是本次唯一「可被單元測試直接驗證」的模組，所以設計決策全部集中在這裡：

- `LIGHT: dict[str, str]`、`DARK: dict[str, str]` — 第 4.1 節的 token 表。
- `TYPE_SCALE: list[str]`、`TYPE_WEIGHTS: list[int]` — 第 4.4 節。
- `FONT_STACK: str` — `'"Figtree", "Noto Sans TC", sans-serif'`。
- `relative_luminance(hex: str) -> float`、`contrast_ratio(a: str, b: str) -> float` — WCAG 公式，純函式。
- `css(mode: str) -> str` — 產生要注入的 CSS 字串。

不 import streamlit 是刻意的：這樣測試不需要啟動 Streamlit runtime，跑得快、也不會被 UI 細節污染。

### 7.2 `.streamlit/config.toml`（改寫）

用 `[theme]` 放共用設定（字型、圓角、字級），`[theme.light]` / `[theme.dark]` 放兩套顏色。
Streamlit 1.60 已支援下列鍵（已在本機 1.60.0 驗證）：
`font`、`headingFont`、`headingFontSizes`、`headingFontWeights`、`baseFontSize`、`baseRadius`、`buttonRadius`、
`backgroundColor`、`secondaryBackgroundColor`、`textColor`、`primaryColor`、`borderColor`、`linkColor`、
`chartCategoricalColors`、`showWidgetBorder`。

`theme.font` 接受 `"<字型名>:<CSS 網址>"` 格式，可直接指向 Google Fonts。

**config.toml 的值必須與 `daibu/theme.py` 的 token 一致**，且這件事要有測試把關（見 7.4）。

### 7.3 `daibu/ui.py`（改寫 `apply_styles`）

- `@import` 載入 Figtree 與 Noto Sans TC。
- 把 `theme.py` 的 token 輸出成 CSS 變數，並用 `@media (prefers-color-scheme: dark)` 與
  Streamlit 的深色 class 兩種方式覆蓋，確保跟著模式切換。
- 主要按鈕文字色、焦點樣式、卡片、chip、動效等第 6 節的規範。
- 新增 `brand_lockup()`：輸出內嵌的吉祥物 SVG + 文字標誌（給側邊欄與首頁 hero 用）。
  **必須內嵌 SVG，不可用 `<img>`** —— `assets/mascot.svg` 用 CSS 變數上色，`<img>` 載入時變數不會生效。

### 7.4 測試策略（樣式要怎麼測）

視覺好不好看測不出來，但**設計決策**測得出來。分三層：

1. **token 與對比度（純函式，快）**：色碼正確、對比度紅線全部成立、字級數量與 h1–h6 對齊。
2. **設定檔契約**：讀 `.streamlit/config.toml`，斷言其中的顏色與 `theme.py` 的 token 一致 ——
   防止「改了 Python 卻忘了改設定檔」這種只有肉眼看得到的漂移。
3. **頁面煙霧測試（`AppTest`）**：四頁載入不報錯、關鍵元素存在（首頁有主要 CTA、選題頁顯示分數、
   流水線有五欄、成效頁有建議卡）。
