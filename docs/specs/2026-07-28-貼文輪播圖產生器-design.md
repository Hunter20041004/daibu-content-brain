# 貼文輪播圖產生器 — 設計規格

> 建立於 2026-07-28。由 🧠 Claude 與使用者在同日的設計對話中定案。
> 實作交給 🖐 Codex，TDD 計畫另見 `docs/plan-carousel.md`。

## 一句話

讓「AI 新創介紹」這個主題，從選題到產出一整套可以直接發的 IG 輪播圖。

---

## 1. 背景

### 現況

工具目前走到「標記已發」為止，貼文的**正文是使用者自己在 `st.text_area` 手打的**，
AI 只負責產標題候選。圖完全沒碰。

### 觸發這一輪的問題

`docs/open-questions.md` 長期卡著一條：**「圖片生成服務多數付費」與「只用免費額度」牴觸**，
導致產圖功能一直沒辦法開始設計。

### 這條衝突已解除

設計對話中確認了兩件事，衝突自然消失：

1. **貼文的圖是「文字圖卡」，不是 AI 生成的插畫。** 本質是網頁排版後截圖，零成本、
   中文字永遠正確、每張風格一致。
2. **插畫／吉祥物是「模板的一部分」，不是每則貼文重生成一次。** 素材做好收進專案重複使用。

**結論：本專案的產品程式碼不會呼叫任何付費的圖片生成服務。** `open-questions.md`
裡那條可以結案。

---

## 2. 範圍

### 做

- 修「AI 新創介紹」的選題，讓它產得出**具體公司**
- 為該主題做**一套** 7 頁輪播模板
- AI 產七格草稿 → 使用者逐格改 → 出圖 → 打包下載

### 不做（本輪明確排除）

- 其他兩個主題的模板（「AI 近期大事」「本週熱門 Claude/Codex Skill」）
- 模板編輯器（使用者不能在工具裡改模板；模板是專案裡的檔案）
- 分平台產文字（Threads／IG／LinkedIn 各寫各的）
- 呼叫任何圖片生成 API
- 每則貼文專屬的手繪插畫

---

## 3. 兩階段拆分

階段一是階段二的**前提**——沒有公司名，第二階段的 AI 不知道要介紹誰。
但階段一自己就有價值，所以中途停下來交付的是「選題變好用了」，不是半個功能。

| 階段 | 內容 | 停在這裡的話 |
|---|---|---|
| **一** | 選題產得出具體公司 | 候選從「不知道在講誰」變成看四行就能決定 |
| **二** | 產輪播圖 | 完整功能 |

---

## 4. 階段一：選題產得出具體公司

### 4.1 主題本質（定案）

**「AI 新創介紹」＝ 介紹一家具體的公司，以及他們如何運用 AI。**

不是「介紹一個讀者可以馬上用的工具」，所以不談定價、不談讀者怎麼操作。
讀者的位置是「來認識這家公司在幹嘛」。

### 4.2 來源收斂

目前這個主題綁了資料庫裡**全部 15 個來源**（含 Reddit r/LocalLLaMA、GitHub、
Anthropic Skills Releases），對「找一家值得介紹的新創」沒幫助，只灌雜訊。

收斂成 5 個：

| 來源 | fetch_type |
|---|---|
| Product Hunt AI | rss |
| Y Combinator Blog | search |
| a16z | rss |
| TechCrunch | rss |
| INSIDE | search |

其餘 10 個來源**只從這個主題解綁，不刪除**（其他主題仍在用）。

### 4.3 候選長什麼樣

使用者在審核那一刻需要看到四樣東西：

| 顯示的東西 | 存在哪 | 說明 |
|---|---|---|
| 公司名 | **`ideas.company`（新增）** | 唯一新增的欄位 |
| 一句話在做什麼 | `ideas.title` | 沿用，語意本來就是「標題」 |
| 為什麼現在值得講 | `ideas.angle` | 沿用，語意本來就是「切角」 |
| 出處連結 | `ideas.source_url` | 欄位早就有，目前全空，這輪要真的填 |
| **原文片段** | **`ideas.source_excerpt`（新增）** | 見 4.5 |

### 4.4 產候選的指令改寫

不再叫 AI「想一個標題」，改成：**從抓回來的素材裡找出一家具體的公司**，
針對每一則候選回答四件事（公司名／一句話定位／為什麼現在值得講／出處）。

指令中要明確禁止：
- 產出沒有公司名的通用觀點文（目前 6 則舊候選全部是這種）
- 憑印象編造素材裡沒出現的公司

若某一輪的素材裡找不到足夠的公司，**寧可少產幾則，也不要湊數**。

### 4.5 為什麼要存原文片段

`daibu/fetch/collector.py` 的 `collect()` 回傳 `Material(title, url, snippet)`，
餵給 LLM 之後就丟掉了——**資料庫裡一個字都沒留**。

到了階段二要「標出每格的依據」時，原始素材早就不在。所以階段一就要開始存：
每則候選存下它所根據的那一段 `snippet`。

不採用「產草稿時重新抓 `source_url`」的原因：網頁可能改版、加付費牆、或整篇消失，
而依據必須在採用當下就固定下來。

### 4.6 舊資料

現有 6 則候選沒有 `company` 與 `source_excerpt`，顯示為「未指定」，**不得因此壞掉或被刪除**。
專案已有資料搬遷的既有做法（見 `daibu/db.py` 與 `tests/test_db_migration.py`），照抄。

## 5. 階段二：產輪播圖

### 5.1 七格結構（定案）

| 頁 | 頁型 slug | 這一格填什麼 | 吉祥物姿勢 |
|---|---|---|---|
| 1 | `cover` | 一句鉤子 ＋ 公司名 | `wave` |
| 2 | `who` | 哪裡的公司、成立多久、做哪個領域 | `point` |
| 3 | `problem` | 這個領域原本卡在哪 | `think` |
| 4 | `how-ai` | **核心頁**：AI 在他們的產品裡扮演什麼角色 | `point` |
| 5 | `results` | 成果、規模、誰在用 | `cheer` |
| 6 | `why-care` | 呆一布的觀點：這代表什麼趨勢 | `note` |
| 7 | `cta` | 追蹤／留言 | `wave` |

第 4 頁是這個主題的心臟，其他頁可以壓縮，這頁不行——沒有它，這就只是一則公司簡介。
第 6 頁是呆一布跟科技媒體的差別，少了它就只是在轉述新聞。

### 5.2 資料模型：另開一張表

七格不塞進 `ideas`，另開 `carousel_pages`，一頁一列：

| 欄 | 型別 | 說明 |
|---|---|---|
| `id` | INTEGER PK | |
| `idea_id` | INTEGER FK → `ideas.id` | 見下方「刪除與淘汰」 |
| `page_no` | INTEGER | 1–7 |
| `page_type` | TEXT | 見 5.1 的 slug |
| `heading` | TEXT | 圖上的標題 |
| `body` | TEXT | 圖上的內文 |
| `grounding` | TEXT | `source` 或 `model`，見 5.4 |
| `source_quote` | TEXT | 這一格依據的原文片段（`grounding=model` 時為空） |
| `updated_at` | TEXT | |

**為什麼不是一個 JSON 欄位**：要逐頁編輯、之後可能要調順序、要能單獨重產某一頁。
拆成一頁一列，這些都是單純操作；擠成一坨就得拆字串。

**刪除與淘汰的差別**（這個專案上一輪出過「刪主題產生孤兒題目」的資料錯誤，不可重蹈）：

| 動作 | 對 `carousel_pages` 的影響 |
|---|---|
| 題目被**淘汰**（`status='已淘汰'`） | **保留**。淘汰可復原，草稿跟著留著 |
| 題目被**刪除** | 一起刪，不留孤兒列 |
| 主題被刪除（連帶刪掉底下題目） | 一起刪，不留孤兒列 |

刪主題時的告知訊息（現有行為是「會刪掉幾則題目」）要一併說明會刪掉幾份輪播草稿。

### 5.3 產草稿

**輸入**：`company`、`title`、`angle`、`source_excerpt`。
**輸出**：七格，每格含 `heading`、`body`、`grounding`、`source_quote`。

字數上限（模板容得下的量，實作時依實際渲染微調並寫進指令）：

| 欄位 | 上限 |
|---|---|
| `cover` 的鉤子 | 20 字 |
| 公司名 | 16 字元 |
| 內頁 `heading` | 14 字 |
| 內頁 `body` | 60 字 |

指令中要寫明超過就自己縮短，不可截斷成半句。

### 5.4 依據標記（重要）

`source_excerpt` 只是一段摘要，不可能包含七格所需的全部資訊，所以 AI 一定會用到
自己的知識補足——**那正是幻覺會出現的地方**。

因此每一格要自己標明：

| `grounding` | 意思 | 介面呈現 |
|---|---|---|
| `source` | 這格寫的東西在原文裡找得到，`source_quote` 附上那一句 | 一般樣式，附可點的來源連結 |
| `model` | 原文沒有，AI 從自己的知識補的 | **明顯標示「需查證」** |

最容易被標成 `model` 的是第 5 頁的數字（融資金額、用戶數、成立年份）——AI 講這些
特別有自信也特別容易錯。

**不做任何強制勾選的關卡。** 使用者的立場是「產出來的東西都要經過查證」，
所以設計的責任是把查證成本壓低（標出哪幾格可疑、附上原文可點），
查不查、查多細是使用者的判斷，工具不擋。

### 5.5 介面

位置：**選題頁 → 右邊工作區 → 已採用的那則底下**。不另開一頁——它跟那則題目綁死，
獨立一頁會逼使用者在兩頁之間跳來跳去對照原文。

三個狀態：

| 狀態 | 畫面上有什麼 |
|---|---|
| 還沒產 | 「產生輪播草稿」按鈕，旁註「會呼叫 AI，約 10 秒」 |
| 草稿產好 | 七個區塊：頁型標籤 ＋ `heading` 欄 ＋ `body` 欄 ＋ 依據標記（可點回原文） |
| 圖產好 | 七張縮圖 ＋「下載全部」（zip，檔名 `01-cover.png` 這樣編號） |

草稿的存檔必須走**跟正文 `save_body_draft()` 一樣的機制**——這個專案上一輪
發生過「正文草稿在頁面重跑時靜默消失」，不可重蹈。

### 5.6 出圖

**Playwright**（使用者已拍板）。用程式開一個看不見的瀏覽器，載入模板網頁、截圖。

| 備援選項 | 為什麼不選 |
|---|---|
| Pillow | 排版要自己算座標，中文自動換行、圓角、陰影、pattern 都得手刻 |
| html2canvas | 對字體與部分 CSS 支援不完美，**容易「預覽好看、匯出走樣」** |

選 Playwright 的唯一但關鍵的理由：**匯出的圖必須跟預覽一模一樣**。
這是整個功能的核心價值。

代價：`requirements.txt` 多一行 `playwright`，且首次要跑 `playwright install chromium`
（約 150 MB）。README 與 `AGENTS.md` 要補上這個安裝步驟。

## 6. 模板規格

### 6.1 尺寸

**1080 × 1350（4:5 直式）。** IG 輪播現在的主流比例，佔螢幕高度比 1:1 多約三成。

一套輪播裡**所有圖必須同比例**，中途換會被 IG 自動裁切。
之後若要出 Threads／LinkedIn 版本，是另外做一套版面，不是把同一張拉扁。

### 6.2 結構：外框底色 ＋ 大白卡

**亮感來自白卡，不是底色。** 早期版本把封面做成滿版純色，怎麼調都沈；
照使用者現有 IG 貼文的真實結構重做之後才對。

```
外框（淡藍）
 ├ 左下：白色斜線 pattern（CSS）
 ├ 右上：白色點陣 pattern（CSS）
 ├ 白卡（inset 6.5%，圓角 5.5%，柔和陰影）
 │   ├ 頁型標籤（小、字距寬、淺藍）
 │   ├ heading（大）
 │   ├ body
 │   └ 吉祥物
 └ @呆一布（白卡外，右下）
```

### 6.3 配色

| 用途 | 色 |
|---|---|
| 外框底色 | `#D5E6F4` |
| 白卡 | `#FFFFFF` |
| 文字 | `#2E5C9E` |
| 次級文字／標籤 | `#8FA9C8` |
| 重點底線 | `#F6BCC8` |
| 點綴 | `#E8912D` |
| 吉祥物機身 | `#5B8FC9` |

**這些顏色一律寫死，不得使用會隨深淺模式變動的 CSS 變數。**
貼文圖是要匯出的成品，不是介面。設計過程中就踩過一次這個坑
（白卡版之前的稿在深色模式下標題整個隱形），與專案上一輪驗收抓到的
「彈窗文字隱形」是同一類問題。

### 6.4 字體

**芫荽（Iansui）**，中英文都用（使用者已確認英文不另配字型）。
開放字型授權、可商用，Google Fonts 上有。

**只有一個字重（400），沒有粗體。** 因此圖卡上的層次只能靠**字級大小**與**顏色深淺**
拉開，不能靠字重。這反而更接近手寫的感覺。

字型檔要**下載進專案**（`assets/fonts/`），出圖時不依賴網路——否則 Playwright
在無網路環境會退回系統字型，匯出的圖跟預覽就不一樣了。

### 6.5 吉祥物素材

**由 Codex 直接寫 SVG**（使用者已拍板；手上沒有 Figma／Illustrator 原始檔）。

現有 `assets/mascot.svg` 本來就是幾何 SVG（長方形、圓形、path 組成），
可讀可改。姿勢變體＝加手臂 path、改嘴型、改眼睛。

五種姿勢，放在 `assets/mascot/`：

| slug | 姿勢 | 用在 |
|---|---|---|
| `wave` | 揮手打招呼 | cover、cta |
| `point` | 指引講解 | who、how-ai |
| `think` | 托腮思考 | problem |
| `cheer` | 舉手歡呼 | results |
| `note` | 拿著筆記 | why-care |

不採用「呼叫生圖 API」的原因：需要金鑰、每次結果不同，而且 Codex 沒有視覺判斷能力，
產完仍得由使用者一張張挑——真正花時間的是挑圖，不是生圖，那條路省不到人的工。

**已知落差**：現有 SVG 是幾何簡化版，使用者 IG 上那隻是手繪版（線條有粗細變化、
有手的抖動感）。SVG 做得到「圓潤可愛、風格一致」，做不到「像人手畫的」。
若日後取得原始向量檔，直接替換 `assets/mascot/` 即可。

### 6.6 檔案位置

```
daibu/cards/templates/ai-startup.html   模板本體（版面規則）
daibu/cards/templates/ai-startup.css    配色、字體、pattern
assets/fonts/                           芫荽字型檔
assets/mascot/                          五種姿勢的 SVG
```

模板是**專案裡的檔案**，不是資料庫裡的設定——可以版本控管、改壞了能還原，
之後要加第二套模板就是再放一組檔案。

## 7. 已知風險與測試要求

這個專案上一輪的教訓是「99 個測試全綠，但四個會弄壞資料的問題一個都沒抓到」，
共同點是它們都跨越了單一函式的邊界。以下三個是同類風險，**每一條都要先寫出會失敗的
測試再修**：

### 7.1 匯出的圖跟預覽不一樣

成因：字型沒載到、圖檔路徑錯、pattern 沒渲染完就截圖。

要求：**真的產一張圖出來檢查像素**（例如取樣白卡區域確認是白的、外框區域確認是
`#D5E6F4`、確認字型有載入），不能只測函式回傳值。這是契約測試，不是 mock。

### 7.2 字太長爆版

成因：AI 產的字沒有字數限制，塞進固定版面會溢出或被裁掉。

要求：模板要有明確字數上限（見 5.3），AI 指令裡要寫，且要有**超長字串的測試**——
餵一段遠超上限的文字，確認輸出的圖沒有文字溢出畫布。

### 7.3 草稿靜默消失

成因：Streamlit 頁面重跑的生命週期。這個專案上一輪就發生過（正文草稿不見）。

要求：七格草稿的存檔走跟 `save_body_draft()` 一樣的機制，並補上重跑後草稿仍在的測試。

## 10. 決策紀錄

依對話順序，記下拍板內容與理由，避免日後重複討論：

| # | 決定 | 理由 |
|---|---|---|
| 1 | 文字圖卡，不用 AI 生成插畫當主視覺 | 零成本、中文字永遠正確、風格一致 |
| 2 | 模板綁**主題**不綁選題 | 同一個單元的貼文長得一致，設定一次自動套 |
| 3 | 多張輪播，不是單張 | IG 知識型帳號的主流格式 |
| 4 | 每頁文字由 AI 產草稿、使用者逐頁改 | 手打 7 頁太累，純 AI 不改不能用 |
| 5 | 先只做「AI 新創介紹」一套模板 | 走通整條路再擴充 |
| 6 | 視覺延續使用者現有 IG 語言，不另起爐灶 | 品牌一致性；且使用者已有明確既存風格 |
| 7 | 插畫是模板的一部分，只做一次 | **成本衝突因此解除** |
